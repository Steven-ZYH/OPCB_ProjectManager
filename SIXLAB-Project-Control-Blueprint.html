            产品定义：SIXLAB Project Control 是原生 macOS、本地优先、审计驱动的项目控制中心。菜单栏保留为低干扰快捷入口，主窗口负责完整工作；Apple 玻璃负责导航和操作层，OPCB 白禅负责内容和证据层。
            当前基线AppKit 菜单栏应用，约 1 万行核心 Swift/构建测试；单次 swiftc 全量编译，AppDelegate 和 Dashboard 承担过多职责。
            推荐 V1Swift Package 模块化内核 + SwiftUI 主窗口 + AppKit NSStatusItem/NSPopover；运行时先用进程内 Actor，不急于引入通用 daemon。
            后续隔离P4 仅把 Secret Broker 下沉到最小权限 XPC Helper；P5 有真实多设备需求后再增加 LaunchAgent/远程 Agent。
            所有写操作唯一通道　Prepare → Refresh facts → Policy → Confirm → Execute → Verify → Audit

            兼容策略macOS 26+ 采用系统 Liquid Glass；macOS 13–15 使用 standard material / NSVisualEffectView，并支持降低透明度。

            无损建立可重建基线

            把当前已运行但未提交的实现，变成可从干净 checkout 重建和验证的版本事实源。

            交付物

            • 恢复分支与原子基线提交
            • 从 origin/main 建立干净集成线
            • 源码、Harness、安装包证据清单

            退出门

            • 干净 checkout 可构建
            • 12 项 Harness 与渲染对比通过
            • 现有能力逐项验收，无密钥进入 Git

            实施边界

            开始条件冻结当前工作树，不进行 rebase、reset、clean 或覆盖式同步。
            架构变化只改变版本事实与可重建性，不改用户功能和外部行为。
            持续拓展方式先把可重建基线做成自动检查；后续每个模块迁移都必须复用同一套行为基线。
            权限边界本地保全可执行；提交、推送、PR、安装替换均需分别授权。
            失败回退保留原分支、安装包、二进制哈希、binary patch 和未跟踪文件清单，任何一步失败都回到只读状态。

            冻结并盘点当前事实

            先确认当前运行版到底由哪些源码、未跟踪文件、缓存、安装包和远端依赖组成，避免后续保全遗漏。

            最小可实施拆分

            • 记录 branch、HEAD、origin/main、ahead/behind、status 和完整 diff 统计。
            • 列出未跟踪文件、Harness、安装包路径、运行进程、签名和 SHA-256。
            • 把现有功能按 PR、Session、路线图、审核机、缓存、通知拆成验收清单。

            落点与验收

            涉及模块整个仓库，只读；重点是 native/、tests/、review-worker/、build/harness/。
            必须产物版本事实清单、功能清单、文件清单、安装产物清单。
            完成证据清单中的 SHA、文件数、diff 统计与 handoff 逐项一致。
            下一层扩展把本阶段形成的证据和契约转成后续阶段可重复使用的测试与门禁。
            所需权限只读，无需提交或外部写权限。

            失败与恢复

            失败信号只记录 Git commit，遗漏未提交源码或把 Harness 缓存当源码。
            回退方式不修改任何状态；发现不一致时停止并补清单。
            时间是规划窗口，不是工期承诺。每个工作包都有独立产物和证据；阶段退出门没有全部通过，就不进入下一阶段。
