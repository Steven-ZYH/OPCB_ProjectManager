## 一句话目标

在不接真实 provider、timer、UI 或 Runtime Actor 的前提下，为 P1.4 的
`NormalizationEvent`／`NormalizationDecision` 建立 SQLite append-only 事件账本、
同事务 projection 更新和确定性 rebuild/recovery，使 normalized state 可以跨进程验证、
审计并从 ledger 重建。

## 已确认起点

- P1.4-A 已关闭；最后一次已验证 live main 为
  `7d50c14e9e926a3bc3a3a31c9554ff6f63403642`，开始时必须重新查询。
- `StateNormalizer` 已是无 I/O 的确定性 reducer，覆盖 begin/observation/expire。
- `NormalizationEvent<Value>`、`NormalizationDecision`、`NormalizedProjection<Value>`
  已 Codable；资源身份为精确、大小写敏感契约。
- `InMemoryProjectionStore` 提供 expected-generation CAS，但明确不是 durable fact source。
- `docs/P1.5-event-projection-persistence-interface.md` 已定义 ledger、projection、transaction
  与 deferred boundary。
- `ProjectControlStore` 尚无 SQLite 接线、schema、transaction、rebuild 或 recovery。
- `AuditEvent.attributes` 只允许受控 shadow 计数字段，不得扩成任意 JSON/value 容器。

## 为什么现在做 P1.5

Policy 与 Runtime 都需要可验证的 current facts；若先让 Runtime 长期拥有 refresh，内存
projection 会在崩溃后丢失且无法解释状态来源。先建立 ledger -> transaction -> rebuild
闭环，可让后续 Policy 读取有证据位置的 projection，也避免把 AppDelegate 或 SQLite
回调变成第二个状态 reducer。

## 本 PR 必须交付

1. **SQLite 边界与 schema**
   - 在 `ProjectControlStore` 内接入可审查的 SQLite system-library 边界；Domain 继续不
     依赖 SQLite、AppKit、Process、shell 或 provider。
   - 建立 schema metadata/version、append-only event ledger、materialized projection 和
     last-applied ledger position。
   - 数据库文件及辅助文件使用私有权限；未知未来 schema/version 必须 fail-closed。
2. **版本化 typed record**
   - 定义 normalization record schema，至少绑定 event ID、ledger position、resource、
     generation、correlation、source、event type、payload version、decision 和时间证据。
   - value/failure payload 与 value-free audit decision 分层；不得把 provider message、值
     或 secret 填入 `AuditEvent.attributes`。
   - 为 encoded `Value` 定义稳定 type discriminator/codec version，拒绝类型错配。
3. **单事务提交**
   - append event、保存 typed decision、expected-generation projection CAS、更新
     last-applied position 必须在一个 SQLite transaction 中完成。
   - event ID 和规定的 correlation identity 重试必须幂等；相同 ID 不得重复推进 projection。
   - CAS/late/conflict/rejected decision 也应有有序审计记录，但不得伪造成功 projection。
4. **确定性 rebuild**
   - 从有序 ledger 逐条调用现有 `StateNormalizer`，不得复制第二套 reducer 逻辑。
   - 支持空 projection 全量重建、重复 rebuild、按 checkpoint 恢复或安全重启。
   - rebuild 结果必须按资源隔离，保持 exact-spelling identity；不得从 sibling resource
     推断项目整体健康。
5. **migration、备份与恢复**
   - 覆盖首次建库、当前 schema reopen、受支持 migration、未知未来版本、损坏库／记录、
     中断 transaction 和备份恢复。
   - 替换现有 materialized projection 前使用可回滚步骤；失败不得覆盖唯一有效状态。
6. **测试与文档**
   - 添加 transaction fault injection、跨进程 reopen、replay/rebuild、migration、并发 writer
     和隐私反例测试，并接入 `test-native.sh`／CircleCI。
   - 记录数据库位置、schema、durability 设置、backup/recovery runbook 和 P1.6 消费端口。

## 关键测试矩阵

- begin -> value、begin -> failure、expire 的 live write 与 full rebuild 结果完全一致。
- generation 2 已提交后，generation 1 的晚到记录可审计但不能倒退 projection。
- 相同 event ID/correlation 重试不重复追加、不重复推进；不同 payload 的 ID 冲突
  fail-closed。
- event append 与 projection update 之间注入故障时 transaction 全部回滚；重启后无
  “有 projection 无 event”或“不可恢复的 event 无 projection”。
- projection 表清空后可只从 ledger 恢复；连续 rebuild 幂等。
- project/resource 大小写变体保持不同身份，canonical/equality/hash/SQLite lookup 一致。
- 一个资源的 success 不改变 sibling 的 unknown/partial/unreachable。
- 旧 schema 可迁移，未知未来 schema 拒绝打开；损坏记录不被跳过并伪装成功。
- 数据库 reopen 后 ledger position、projection generation、correlation 和 decision 不漂移。
- audit decision 不包含 value、provider message、token/secret/private-key 正文。
- 完整 `swift test`、`test-native.sh`、bundle source binding、codesign 保持通过。

## 停止条件

- 需要修改或清理受保护脏工作树才能继续；
- SQLite schema 只能存 arbitrary JSON，缺少 type/version/identity 契约；
- append 和 projection 更新不能在一个事务或可证明恢复协议内成立；
- rebuild 需要复制 reducer、读取 live provider 或使用未记录 wall clock；
- 为通过测试需要跳过损坏 event、弱化 unknown/partial/unreachable 或覆盖唯一有效库；
- 需要 Policy、Runtime、UI、真实 timer、外部命令、安装或部署才能成立；
- live main/head 漂移但证据未重跑。
