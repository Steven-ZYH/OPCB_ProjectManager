## 实现证据

- 新增 `ProjectControlRuntime` target。单一 actor 持有 exact-resource refresh lease、单调
  generation、cancellation、business schedule、legacy callback activity claim 与 projection
  `AsyncStream`；Domain／Store／Adapters 均不反向依赖 Runtime。
- refresh 先 durable `.begin`，再执行 injected adapter observation，最后提交 observation 或
  typed failure。重复并发请求返回 in-flight；取消并重启后，旧 lease 的 late result 不能覆盖
  新 generation。
- AppDelegate 的 GitHub snapshot、Codex session activity、review-machine status 和 roadmap
  四类业务调度已改由 Runtime actor 管理；旧 repository Set 和三个单例 in-flight flag 已移除。
  `AppTheme` 视觉动画 timer 仍保留在 UI 层。
- 新增 `RuntimeJournalStoring`、`ClosedRuntimeJournal`、测试用 `InMemoryRuntimeJournal` 与
  authoritative `SQLiteRuntimeJournal`。SQLite journal 使用私有 0600 文件／0700 目录、
  schema version、integrity check、FULL synchronous、busy timeout 与 `BEGIN IMMEDIATE`。
- confirmation 只能从 `PolicyDecision.confirmationRequired` 发行；journal 绑定 token、command、
  action、requirement digest、issued/expires 与 consumed state。unknown、forged、mismatch、future、
  expired、already-consumed 和 identity conflict 均 fail-closed。
- command submit 在执行前重新运行 Policy Engine，并原子 claim token+command。duplicate submit
  返回 durable record，不重复调用 executor。P1.7 只注入 closed/fake executor，不接真实 provider。
- claim 后、完成记录前崩溃时，durable state 保持 `claimed`（unknown）；不会被错误标记为失败，
  也不会自动重放可能已经发生的副作用。
- Runtime、journal、Domain 和 architecture guard 不引入 shell、Process、URLSession、provider
  literal 或第二份业务 timer authority。
