# P1.6 Policy Engine 启动 Handoff

生成时间：2026-08-12 CST

执行仓库：`Steven-ZYH/sixlab-pr-control`

Handoff 类型：**START HANDOFF**。收到 Steven 明确“开始”或“继续 P1.6”后，可从执行时
live `main` 建立隔离 checkout，完成 P1.6 的实现、测试、分支和 Ready PR。本 Handoff
不授权 merge、App 安装、Worker 更新、真实 command execution、secret 读取或部署。

## 一句话目标

在不执行任何命令、不接真实 provider/runtime/UI 的前提下，建立纯、确定性、fail-closed
的 Policy Engine：把 typed `CommandIntent`、精确作用域的 durable required facts、actor／
environment authority 和 confirmation binding 归约为 typed `PolicyDecision`，明确区分
allow、confirm、deny，并确保 merge、deploy、secret-use 三类权限互不推导。

## 已确认起点

- P1.5 已关闭；执行时必须重新查询 live main，最后已验证 main 为
  `c7ee54ae1e8c33318a414e670fd80c57faa8df87`。
- `StateNormalizer` 是唯一 observation reducer，输出按 `projectID + ResourceRef` 隔离的
  `NormalizedProjection<Value>`。
- `DurableProjectionReading.projection(for:)` 只返回一个 exact resource 的 projection；
  不暴露 SQLite、ledger mutation、provider refresh、timer 或 command execution。
- projection 已携带 freshness、generation、source、observed/expiry evidence、active
  correlation 和 failure classification；unknown/partial/unreachable 不得弱化成 success。
- Registry v1 已有 `policyRefs` 与 capability descriptors，但 Registry 只是配置，不是权限
  或部署事实源。
- `AuditEvent` 已有 intent/confirmation/execution category 和 command ID 约束；其
  `attributes` 仍只允许受控 shadow 计数字段，不得扩成任意 policy payload。
- 当前仓库没有 `CommandIntent`、`PolicyDecision`、required-fact contract、risk model、
  confirmation binding 或 Policy Engine。

## 为什么现在做 P1.6

P1.7 Runtime Actor 需要在接管 timers、adapters 和 command ownership 前获得一个不执行
外部副作用的确定性决策内核。若先实现 Runtime/CommandBus，权限判断会散落到 AppDelegate、
provider 回调或按钮处理器中，形成多个 authority owner，也无法解释某次 allow/deny 使用了
哪些 durable facts。P1.6 先关闭 intent -> fact requirements -> decision 的纯函数闭环。

## 本 PR 必须交付

1. **Typed CommandIntent 与作用域**
   - 定义稳定、Codable、Equatable、Sendable 的 command ID、intent kind、project、target
     resource、actor、environment、requestedAt 和 action-specific binding。
   - 至少覆盖 merge、deploy、secret-use；不得用任意字符串／字典承载 authority 语义。
   - merge intent 必须能绑定 repository/PR/current head/base；deploy 必须绑定 exact artifact
     或 commit 与目标 environment；secret-use 只绑定 capability/scope/purpose，绝不包含 secret 值。
2. **Required facts 与读取边界**
   - 为每种 intent 声明 typed required facts，并按 exact `NormalizedResourceKey` 获取。
   - 通过 P1.5 `DurableProjectionReading` 的只读端口消费 projection；不得读取 sibling
     resource 推断项目整体健康，不得直接查询 SQLite 表或 ledger。
   - 缺失、unknown、stale、partial、unreachable、fetching、source/generation 不匹配和
     future/unsupported fact 必须形成明确 deny/confirm/unsupported 原因，不能默认 allow。
3. **纯 PolicyEngine**
   - evaluator 必须无 I/O、无 wall-clock 读取、无随机数、无 provider、无 timer、无 AppKit、
     无 shell/Process；evaluation time、policy version 和 facts 全部由调用方注入。
   - 输出 typed `PolicyDecision`，至少区分 `allowed`、`confirmationRequired`、`denied`；
     decision 只携带稳定标识、原因、required/missing fact refs 和 evidence binding。
   - 相同 intent + policy version + facts + evaluation time 必须产生相同 decision。
4. **权限不推导与 fail-closed 规则**
   - merge approval 不授权 deploy；deploy approval 不授权 secret-use；secret capability 不授权
     merge、push、文件写入或其他环境。
   - Ready、green CI、mergeable、Registry capability、可读 secret metadata 或已有 confirmation
     中任一单项都不能独立产生 allow。
   - actor、project、repository、head/base、environment、artifact、capability 或 policy version
     任一 scope drift 必须拒绝复用旧 decision/confirmation。
5. **Confirmation binding contract**
   - 定义 value-free confirmation requirement/grant，至少绑定 command ID、intent digest、actor、
     project/target/environment scope、policy version、fact/evidence digest、issuedAt/expiresAt。
   - confirmation 验证只使用注入时间；过期、未来签发、错误 actor/scope、intent/fact drift、
     重复或不支持版本必须 fail-closed。
   - P1.6 不读取 secret、不生成真实签名、不持久化或消费一次性 token；token issuance、
     replay store 和 CommandBus ownership 保留到 P1.7。不得因此把 confirmation 当成 allow。
6. **测试、隐私与架构守卫**
   - 添加 table-driven allow/confirm/deny 测试及 merge/deploy/secret-use 交叉权限反例。
   - 用 P1.5 durable reader 的 fake/SQLite integration fixture 证明 exact-resource fact consumption；
     损坏 ledger 仍由 P1.5 fail-closed，不得在 Policy 层跳过或改写为 missing-success。
   - 覆盖 stale/partial/unreachable/unknown、missing fact、source/generation drift、confirmation
     scope/expiry/version drift、同输入确定性和 decision privacy。
   - 接入完整 `swift test`、`test-native.sh`、source binding、codesign 与 CircleCI。
   - 记录 policy vocabulary、decision matrix、required-fact mapping、confirmation/deferred runtime
     boundary 和 P1.7 消费端口。

## 最小决策矩阵

| Intent | 必需事实示例 | 不足时默认 | 不得推导 |
|---|---|---|---|
| merge | open/non-draft、exact head/base、current-head approval、checks、threads、mergeability | deny 或 confirm；缺失/旧 head 一律 deny | deploy、secret-use |
| deploy | exact merged/artifact identity、target environment、独立 deploy authority、required facts freshness | deny；高风险动作可要求 exact confirmation | production、其他 environment、secret-use |
| secret-use | capability allowlist、actor/project/environment/purpose scope、value-free confirmation | deny 或 exact confirmation | secret value、merge、deploy、任意 shell |

该矩阵是 typed rule 的验收下限，不授权接入真实 GitHub、deployment 或 secret provider。

## 关键测试矩阵

- 相同事实下 merge allow 不会让同 command/actor 的 deploy 或 secret-use 变为 allow。
- PR head/base 任一变化后，旧 approval/decision/confirmation 不可复用。
- CI green 但无 current-head approval、存在 unresolved thread 或 mergeability unknown 时 deny。
- deploy target 从 test 改为 staging/production 时必须重新决策；低环境授权不能向上继承。
- secret capability 名称相同但 project/environment/purpose 不同，旧 grant 拒绝。
- required fact missing/unknown/unreachable/fetching 不能被 sibling resource success 覆盖。
- stale/partial 只能按显式 rule 产生 confirm/deny，不能被通用 truthiness 当作 healthy。
- evaluation time、policy version、facts 和 intent 相同，decision bytes/digest 稳定。
- confirmation 过期、未来签发、错误 actor、scope drift、fact digest drift 和版本不支持均拒绝。
- decision/audit 不包含 provider message、projection value、secret/token/private-key 正文。
- 完整 `swift test`、`test-native.sh`、bundle source binding、codesign 保持通过。

## 明确不做

- 不执行 merge、push、deploy、rollback、secret retrieval、shell、SSH 或任何外部写入。
- 不接真实 GitHub、Session、Roadmap、审核机、环境或 secret provider。
- 不建立 CommandBus、outbox、token replay store 或 side-effect executor。
- 不新增 Timer/DispatchSource，不迁移 AppDelegate 的 timer/cancellation ownership。
- 不建立 Runtime Actor、projection subscription 或长期 refresh owner。
- 不修改 Registry v1 正式配置、UI、Facade mode，不加入 `candidatePrimary`，不切生产读路径。
- 不安装 App、不更新 Worker、不部署 staging/production。

## 推荐实现顺序

1. 先写 merge/deploy/secret-use 不相互授权及 missing/stale fact 的失败测试。
2. 定义 typed intent/scope/required-fact/decision/confirmation vocabulary 与 validation。
3. 实现无 I/O 的 deterministic PolicyEngine 和 action-specific rule mapping。
4. 通过窄 consumer 把 exact durable projection 映射为 typed policy facts；不得复制 normalizer。
5. 完成 confirmation drift/expiry/version、privacy 和 architecture negative tests。
6. 运行完整 package/native Harness；刷新 live main 并做 merge-tree/diff-check。
7. 创建 Ready PR，请求 `miaopantao`，等待 current-head 独立审核。

## PR 与权限规则

- 分支使用 `codex/` 前缀。
- PR 必须列出 exact base/head、intent/decision schema、required-fact matrix、confirmation
  binding、确定性证据、fail-closed 反例和 deferred runtime boundary。
- 作者侧实现、验证与风险披露完成后标记 Ready，并请求 `miaopantao`。
- 不主动请求或 @ 通知 Xia Mingsheng；不改变其 review 权限。
- 任一 push 后重新读取 current head、approval、checks、threads、mergeability 和 live base。
- 旧 SHA 的审核不可复用；Ready/approval 均不等于 merge、安装或部署授权。

## 停止条件

- 需要修改、同步或清理受保护脏工作树才能继续；
- policy 需要读取 sibling resource、live provider、SQLite internals 或未记录 wall clock；
- required facts 只能表示为 arbitrary JSON/string dictionary，缺少 type/version/scope；
- unknown/partial/unreachable/stale 被弱化成 allow，或缺失事实被当作成功；
- merge、deploy、secret-use 能相互推导，或 confirmation 未绑定 exact intent/facts/scope；
- 为让 P1.6 成立必须执行命令、读取 secret、引入 Runtime Actor/timer/UI/切流；
- live main/head 漂移但证据未重跑。
